# WormSoft Limit Monitor

Расширение для Chrome, которое мониторит остаток лимита провайдера **WormSoft** (ai.wormsoft.ru).

## Возможности

- Опрос `GET https://ai.wormsoft.ru/api/v1/account/limits` **каждую минуту** (через `chrome.alarms`, работает даже с закрытым окном).
- Остаток кредитов прямо на **иконке в тулбаре** (`2.2M`, `850k`…):
  - цвет — **плавный градиент от зелёного (100%) к красному (0%)** по ориентиру по тарифу (доля оставшегося `subscriptionLimit` от зафиксированного максимума); если ориентир ещё не зафиксирован — зелёный; цифры — всегда белый текст,
  - оранжевый — подписка заморожена (`isFrozen`, действуют лимиты Free),
  - красный `!` — ошибка (невалидный ключ, rate limit и т.д.).
- **Popup** с деталями: остаток по тарифу и бусту, тайминги сброса («через 3 ч 20 мин», при наведении — точная дата), тип подписки, предупреждение о заморозке, **процент использования тарифа** (см. «Ориентир по тарифу» ниже). Счётчик остатка и круг-индикатор — тем же **градиентным цветом**, что и бейдж (функция цвета общая — `shared.js`).
- **Ориентир по тарифу**: endpoint не возвращает размер полного лимита подписки, поэтому расширение само запоминает **максимальный зафиксированный** остаток `subscriptionLimit` (самое большое наблюдаемое значение с момента смены тарифа) и показывает процент «использовано» от него. При изменении `subscriptionType` (смена/заморозка тарифа) память сбрасывается, и ориентир определяется заново. Значение хранится локально в `chrome.storage.local` (`quotaMemory`).
- **Пробный запрос (опционально, выключен по умолчанию)**: обновление лимита привязано к первому запросу после предыдущего обновления — счётчик до следующего обновления стартует только с него. Если опция включена, расширение в момент обновления лимита (остаток тарифа подпрыгнул до нового максимума) отправляет минимальный LLM-запрос на `/api/gpt/chat/completions` (`max_tokens: 1`, стоимость — единицы кредитов, заведомо ≤ 100), чтобы запустить счётчик сразу и не откладывать следующее обновление. Модель пробного запроса настраивается.
- **Настройки** (вкладка): URL эндпоинта, API-ключ.
- Кнопки «Проверить сейчас» в popup и на странице настроек.

## Установка (dev-режим)

1. Откройте `chrome://extensions`.
2. Включите «Режим разработчика» (правый верхний угол).
3. «Загрузить распакованное расширение» → выберите эту папку.

## Настройка

Откройте иконку расширения → «⚙ Настройки» (или `chrome://extensions` → «Подробнее» → «Настройки расширения»).

| Поле | Что указать |
|---|---|
| URL эндпоинта | По умолчанию `https://ai.wormsoft.ru/api/v1/account/limits` (документация: https://ai.wormsoft.ru/docs/account/limits) |
| API-ключ | Тот же ключ, что и для LLM endpoint-ов; отправляется в заголовке `Authorization: Bearer <ключ>` |

Ключ хранится **только локально** в профиле браузера (`chrome.storage.local`).

### Пробный запрос (запуск счётчика сброса)

В настройках можно включить «Пробный запрос после обновления лимита» и указать модель (по умолчанию `openai/gpt-5.4-mini`).

Как это работает и почему это безопасно для кредитов:

- **Момент срабатывания** — только когда зафиксирован новый максимум остатка тарифа, то есть лимит только что обновился. В любой другой момент пробный запрос бессмысленен и не делается.
- **Минимальная цена** — запрос отправляется с `max_tokens: 1` на выбранную (дешёвую) модель; стоимость — единицы кредитов, заведомо ≤ 100.
- **Бусты не учитываются** — при активном бусте (`boostLimit > 0`) пробный запрос не отправляется: списание ушло бы в буст-кредиты, а не запустило счётчик тарифа. Пользователь с активным бустом и так делает запросы — они запустят счётчик.
- **Смена тарифа** — при изменении `subscriptionType` пробный запрос не делается: неизвестно, в какой точке цикла находится новый тариф, и списание могло бы уйти вхолостую. Расширение ждёт первого реального обновления лимита (подскока остатка) — только оно является безопасным моментом.
- **Защита от повторов** — одно обновление лимита = максимум одна успешная попытка (`probedMax` в `quotaMemory`); между попытками cooldown 10 минут; после 3 неудачных попыток подряд цикл закрывается без успеха, чтобы не долбить API и не жечь кредиты.
- **Ошибки и заморозка** — при ошибке опроса, заморозке подписки (`isFrozen`) или нулевом остатке пробный запрос не делается.
- Последний результат виден в popup (строка «Пробный запрос») и хранится в `chrome.storage.local` (`probeState`).

Каждый пробный запрос **реально списывает кредиты**, поэтому по умолчанию опция выключена.

## Формат ответа API

```json
{
  "userId": 123,
  "subscriptionType": "payed",
  "subscriptionLimit": 1234567,
  "subscriptionLimitResetAt": 1730000000,
  "boostLimit": 1000000,
  "boostLimitResetAt": 1730003600,
  "totalLimit": 2234567,
  "isFrozen": false
}
```

Все поля `*Limit` — это **остатки**: endpoint не возвращает размер полного лимита, поэтому точный процент невозможно показать — только абсолютные числа и приближённый «ориентир» по наблюдаемому максимуму (см. «Ориентир по тарифу»).

Обрабатываемые ошибки API: `401` (невалидный ключ), `429` (rate limit), `404` (запись пользователя удалена).

## Безопасность

- **API-ключ** хранится только локально (`chrome.storage.local`) и отправляется только в заголовке `Authorization: Bearer` на указанный эндпоинт — никогда в URL, query-строку или логи.
- **Валидация эндпоинта** (`validateEndpoint()` в `background.js`): запрос выполняется только по `https://` и только на хосты `ai.wormsoft.ru` / `*.wormsoft.ru`. При другом URL запрос отменяется, и ключ никуда не улетает (защита от опечаток и спуфинга вида `ai.wormsoft.ru.evil.ru`).
- **Безопасный рендер**: все данные из API в popup и options выводятся через `textContent` (не `innerHTML`), в т.ч. текст ошибок, где может быть `statusText` от сервера.
- **MV3, без `eval` и удалённого кода**; минимальные разрешения (`storage`, `alarms`), сеть — только `https://ai.wormsoft.ru/*`.
- Обработчик `onMessage` принимает сообщения только от собственных контекстов расширения (`sender.id`).

## Ограничения

- Опрос каждую минуту (минимальный интервал для периодических `chrome.alarms` — ровно 1 минута). По документации endpoint можно дёргать хоть каждый запрос.
- Endpoint отдаёт только остатки, поэтому бейдж показывает абсолютное число кредитов. Процент «использовано» в popup — **ориентир** (наблюдаемый максимум, см. выше), а не точный размер лимита: пока расширение не увидит полный остаток после сброса периода, значение может занижать реальный лимит.
- Эндпоинт валидируется перед каждым запросом: только `https://` и только хосты `*.wormsoft.ru` (защита от утечки API-ключа в http или на спуф-хосты) — см. «Безопасность». Для другого хоста нужно поправить `validateEndpoint()` в `background.js` и `host_permissions` в `manifest.json`.
