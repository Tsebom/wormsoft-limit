WormSoft Limit Monitor

Настройки подключения к API провайдера WormSoft.

Документация: https://ai.wormsoft.ru/docs/account/limits. Запрос GET с заголовком Authorization: Bearer <ключ>.
Тот же ключ, что и для LLM endpoint-ов. Хранится локально в этом браузере (chrome.storage.local) и отправляется только на указанный URL.
Экспериментально. Обновление лимита привязано к первому запросу после предыдущего обновления: счётчик до следующего обновления стартует только с него. Если включить, расширение в момент обновления лимита (остаток тарифа подпрыгнул до нового максимума) отправит LLM-запрос, чтобы запустить счётчик сразу. Пробный запрос не делается при активном бусте (бусты не учитываются), при ошибках API и при смене тарифа — до первого обновления лимита. Каждый пробный запрос списывает кредиты.
Квота выходных токенов пробы. Цены моделей — кредиты за 1M токенов (https://ai.wormsoft.ru/api/public/models). Чтобы списание было видно по остатку (≥ 1 кредита), нужно ≈ 40 000 токенов на openai/gpt-6.2-astra (25 кр/1M) → ~1,05 кредита; расширение просит модель вывести числа от 1 до 100000, поэтому запрос упирается в эту квоту. Дешёвые flash-модели даже за максимум токенов списывают доли кредита — остаток не изменится.
